### 1. `audio.paused` is unreliable when autoplay is blocked (systemic)

**Symptom.** When Chrome (or Safari) blocks `audio.play()` because user-activation has expired, the `Audio` element reports `paused === false` and `currentTime === 0` — even though playback never actually started. Every flow gate that reads `audio.paused` to decide whether to fire a fallback timer silently skips, and the game hangs.

**Where this manifests.** Encountered live during the test at every audio-gated round transition. The previous push fixed two instances; the rest were still live.

**Fix applied locally.** Added an `_audioGate(audio, onDone, timeoutMs)` helper near the top of `host-complete_42.html` that listens for `ended`, `error`, and a hard `setTimeout`, and guarantees the callback fires exactly once. Sites refactored to use it or have their `paused`-gated short-circuit dropped:

### 5. Score discrepancy when answers come in after auto-reveal

**Symptom.** During the Round 1 Q1 reveal in this run, only 2 of 4 players had their answers counted. The remaining 2 submitted shortly after `revealAnswer()` had already been called, so their points were dropped.

**Likely cause.** Lines ~2705 in the auto-reveal handler:

```js
if (totalPlayers > 0 && answeredCount === totalPlayers) {
  setTimeout(() => { if (!answerRevealed) revealAnswer(); }, 1000);
}
```

This auto-reveals when **all** players have answered. But the answer-counting in `revealAnswer` only iterates `gameRef.child('answers/' + currentQuestion).once('value')` at the time the function runs. Late-arriving submissions (after the once-fetch) don't get points, and there's no second pass.

**Fix.** Either:
(a) Read `answers/<currentQuestion>` once more inside `revealAnswer` after the answer audio has been playing for 2-3 s, or
(b) Listen on `answers/<currentQuestion>` until the answer audio ends and credit late submissions before advancing.

In real play this only bites if a player taps within ~1 s of the auto-reveal threshold, but my forced-advance scenario hit it cleanly.

**Note.** The discrepancy I saw (Argentina 6, Brazil 7 after Round 1 with all 4 picking the same answers) was partly explained by my forced flow, but the underlying race is real.

### 10. `showRound2Explainer` has a latent crash that my audit silently fixes

Pre-existing line ~3640: `window.round2IntroAudio.addEventListener('ended', ...)` was called when `window.round2IntroAudio` is `undefined` (it's only set by `playRound2Voice`, which fires asynchronously when music ends). This would throw `TypeError: Cannot read properties of undefined (reading 'addEventListener')` if `showRound2Explainer` was ever called outside the normal flow.

**Why it didn't show up in normal play.** In the normal flow, `playRound2Voice` is invoked synchronously from the music's `play().catch(…)` (in some browsers) before the next line of `showRound2Explainer` runs, so `round2IntroAudio` is defined by the time `addEventListener` runs. On other browsers (where `play().catch` is microtask), this would have thrown — but the throw would be silently caught somewhere and the user would see Round 2 hang.

**Fix.** My audit's `_audioGate(window.round2IntroAudio, …)` call replaces that line and guards `if (audio && typeof audio.addEventListener === 'function')`, so it no longer crashes when `round2IntroAudio` is `undefined`. Pure improvement.

### 13. Several "celebration" overlays leak across round boundaries

Confirmed during this run:
- Match Draw → Bonus Round overlay (#2 above).
- Bonus "PASS! +5 POINTS!" celebration overlay leaked onto Team Talk intro screen.
- Team Talk's "TEAM TALK ARGENTINA — Get ready! Brazil captain is starting…" `team-talk-waiting` div remained on screen after `startRound2Gameplay()` was called.

These all share the same root cause: each round draws its UI as a `position: fixed; z-index: 10000+` div appended to `<body>`, but the previous round's div isn't always removed before the next is appended. They'd be visible to a real player whenever the previous round's celebration animation is still in flight when the next round renders.

**Fix.** Centralised cleanup helper called by every round entry point:

```js
function _clearRoundOverlays() {
  ['match-draw-intro','md-countdown','md-drawing-timer','md-guessing-timer',
   'chain-reveal','md-scoring-screen','team-talk-intro','team-talk-waiting',
   'team-talk-results','team-talk-scores','round1-explainer','round2-explainer',
   'round3-intro','commentary-intro','bonus-screen','bonus-judging','bonus-karaoke',
   'bonus-pass-celebration','blowball-explainer','toilet-paper-alert',
   'goal-posts-intro','scores-review','futbol-reveal']
    .forEach(id => { const e = document.getElementById(id); if (e) e.remove(); });
}
```

Call it at the top of every `startX()` / `showX()` round entry.
